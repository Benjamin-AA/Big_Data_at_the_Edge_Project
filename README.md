# MammAlps adaptive audio and video inference

This project studies accuracy versus compute for camera-trap inference.
MobileNetV3 Large classifies sampled video frames; temporal adaptive inference
stops when predictions are confident enough. Structured channel pruning and INT8
quantization provide further comparisons. In the full pipeline, audio can gate
whether the video classifier runs.

## Installation

From the repository root:

```bash
uv sync
```

Use a compatible PyTorch/torchvision installation for your CPU or GPU. The
optional YAMNet audio notebook requires `uv sync --extra yamnet`.

Download and extract the MammAlps Benchmark I dataset separately; it is not

# Video pipeline

Run the following commands from `Video/`:

```bash
cd Video
```

Video checkpoints and experiment results are not included. Train the baseline
first, then generate the inputs needed by each experiment below. The settings
are examples you can adjust. Generated weights and results stay local; choose
new output paths when you want to keep multiple runs.
CUDA examples require a GPU; experiment commands also support `--device cpu`.

## 1. Train baseline weights

Train a video classifier on the training split. This creates
`checkpoints/baseline.pt`, which subsequent commands load. Initial training uses
ImageNet-pretrained MobileNetV3 weights, downloaded by torchvision on first use.

```bash
uv run baseline.py --epochs 10 --num-frames 16 --batch-size 4 \
  --lr 1e-4 --augment --oversample \
  --checkpoint checkpoints/baseline.pt
```

`--num-frames` sets the sampled frames per video; `--augment` enables training
augmentation; `--oversample` increases sampling of rare classes; `--lr` sets the
learning rate; `--checkpoint` selects the saved weights. Add `--prune` only if you
also want the baseline workflow's fixed 30% pruning/fine-tuning step.

## 2. Evaluate a trained model

```bash
uv run experiment.py evaluate --checkpoint checkpoints/baseline.pt \
  --split test --num-frames 16 --device cpu
```

This loads the baseline you trained in step 1 without further training. Choose validation or test with
`--split`, the inference frame count with `--num-frames`, and CPU/GPU with
`--device`. Results include accuracy, mAP and per-class statistics. Use validation
to choose settings before final test evaluation.

## 3. Experiment with number of frames

```bash
uv run experiment.py frames --checkpoint checkpoints/baseline.pt \
  --frames 1 2 4 8 16 --split val --device cpu
```

The weights stay fixed while the number of uniformly sampled frames changes.
The experiment saves accuracy/mAP, compute and model-only latency comparisons.

## 4. Structured pruning

Pruning physically removes channels from a baseline and fine-tunes each variant:

```bash
uv run experiment.py pruning --checkpoint checkpoints/baseline.pt \
  --num-frames 16 --ratios 0 0.1 0.25 --epochs 3 --lr 1e-4 \
  --device cuda --output-dir results/pruning_16frames
```

Ratio `0` is an unpruned fine-tuning control; `0.1` requests 10% channel pruning.
The output includes weights and full model artifacts such as
`results/pruning_16frames/prune_0p1_full.pt`. Pass these to `evaluate` or `adaptive`
with `--full-model` because their architecture differs from the unpruned model.

Run this step before the quantization and adaptive examples below: they load
`results/pruning_16frames/prune_0p1_full.pt` generated by this command. Choose
a different generated model by changing the checkpoint path.

## 5. Quantization

After steps 1 and 4, compare your baseline and pruned FP32 models against
static INT8 versions on CPU:

```bash
uv run experiment.py quantization --checkpoint checkpoints/baseline.pt \
  --pruned-checkpoint results/pruning_16frames/prune_0p1_full.pt --num-frames 16 \
  --split val --device cpu --output-dir results/quantization_example
```

Calibration uses training data without gradient training. Outputs include
accuracy/mAP, size, latency and exported INT8 backbones. Quantization changes
numerical precision; it is separate from temporal adaptive stopping.

## 6. Adaptive inference

This is **temporal early exit**, with no separate video early-exit neural-network
head. Candidate frames are ordered midpoint-first, then endpoints and finer gaps.
The classifier processes progressively larger frame budgets, averages their
logits and checks the maximum softmax probability. It stops each video when
confidence reaches the threshold; otherwise it processes more frames.

```bash
uv run experiment.py adaptive --checkpoint results/pruning_16frames/prune_0p1_full.pt \
  --full-model --num-frames 16 --split val --threshold 0.9 \
  --device cuda --output-dir results/adaptive_example
```

Easy videos can use fewer frames. All candidate frames are currently decoded
before inference, so savings concern model computation rather than decoding.

### Threshold sweep

```bash
uv run experiment.py adaptive --checkpoint results/pruning_16frames/prune_0p1_full.pt \
  --full-model --num-frames 16 --split val --device cuda --sweep \
  --output-dir results/prune_0p1_sweep
```

Lower thresholds permit earlier exits and less compute, potentially sacrificing
accuracy. Higher thresholds generally use more frames and may improve accuracy;
accuracy is not guaranteed to increase monotonically.

Bare `--sweep` uses thresholds 0.0–0.5 by 0.1, then 0.55–1.0 by 0.05. Supply a
custom list with `--sweep 0.7 0.9 0.99`. The sweep also evaluates a static full-frame
reference. It saves accuracy/mAP, average executed frames and compute per
threshold under `threshold_sweep/`, with CSVs, per-video statistics and Pareto
plots. Use validation sweeps for policy selection; test curves describe held-out
performance.

## 7. Typical experiment workflow

```text
train baseline -> baseline checkpoint
                    +-> frame-count experiment
                    +-> pruning -> pruned checkpoints
                    +-> quantization
                    +-> adaptive threshold sweep -> Pareto frontier
```

To compare pruning levels, run a separate adaptive sweep for each model you
train, using a different output directory. Use the same split and maximum frame
budget across runs. For the unpruned baseline, omit `--full-model`.

## 8. Plot the adaptive frontier

```bash
uv run plot_adaptive_frontiers.py \
  --sweeps results/prune_0p1_sweep/threshold_sweep \
  --labels "10% pruned" --output-dir results/frontier_example
```

Run the threshold sweep in step 6 first. The plotting command reads its generated
`metrics.csv` and `metadata.json` and produces accuracy/mAP versus average compute
plots in PNG/PDF format. To compare multiple models, pass their generated
`threshold_sweep` directories to `--sweeps` and one label per directory to
`--labels`. Always specify your input directories explicitly.

Adaptive sweeps use **FLOPs = 2 × THOP MACs**, scaled by actual frames executed.
Static frame/pruning experiments report fvcore counts, so their raw compute
columns should not be compared directly with THOP values. Compute estimates are not measured energy.

## Important video CLI options

| Option | Meaning |
| --- | --- |
| `--checkpoint` | Weights to load, or baseline save path |
| `--full-model` | Load a trusted full model, including structurally pruned models |
| `--num-frames` | Frames per video; maximum budget for adaptive inference |
| `--split` | Validation (`val`) or test split |
| `--device` | `cpu` or `cuda` for experiments; quantization is CPU-only |
| `--threshold` | Single adaptive confidence threshold |
| `--sweep` | Evaluate multiple thresholds plus a static reference |
| `--ratios` | Channel-pruning fractions |
| `--lr` | Training/fine-tuning learning rate |
| `--output-dir` | Experiment destination; reusing it overwrites outputs |

For command-specific options, for example:

```bash
uv run experiment.py adaptive --help
```
